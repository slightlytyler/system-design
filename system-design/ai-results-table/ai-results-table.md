# AI results table

_Frontend-leaning. Focus: state and schema management for AI-generated UI, without bloated components._

## Prompt

> We build a research assistant for scientific literature. Its main view is a **results table**: each row is a paper, and each column is a question the user asks of every paper, like "sample size" or "primary outcome". An LLM fills in each cell, and each answer comes with a supporting quote the user can inspect.
>
> Cells are generated asynchronously and can take anywhere from a few seconds to over a minute. Some fail. Users add, edit and remove columns while results are still arriving, and they sort and filter by the AI-generated values.
>
> Other teams are about to build more AI features, like a per-paper summary panel and a chat about the selected papers, and they'll face the same problems.
>
> Design the frontend for the results table, in a way that scales to those other features.

Target length: 60–90 minutes. Clarifying questions are answered in [interviewer-notes.md](interviewer-notes.md). Try to ask them yourself before reading it.
